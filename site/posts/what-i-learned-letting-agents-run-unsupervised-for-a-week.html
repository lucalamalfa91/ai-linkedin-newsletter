Agentic Workflows & Multi-Agent Orchestration

What I Learned Letting Agents Run Unsupervised for a Week

Multi-agent orchestration is less about AI magic and more about disciplined workflow design — here's what that looks like in practice.

October 10, 2026

A client engagement last autumn is what really changed how I think about this. We'd built a pipeline — research agent, summarisation agent, a final drafting agent — and handed it off to run overnight on a batch of competitive intelligence tasks. I came back in the morning expecting clean outputs. What I found was a mess: the research agent had looped on a rate-limited API, the summariser had started hallucinating source URLs because the context window was stuffed with garbage, and the drafter had cheerfully produced seven near-identical reports because nobody told it to stop. Total cost for the night: embarrassing. Useful output: close to zero.

That incident crystallised something I now tell every client before we touch multi-agent design: orchestration is not a feature you add on top of agents, it's the actual engineering problem. The agents are almost the easy part. Getting them to hand off work reliably, fail gracefully, and not spiral into expensive loops — that's where the real work lives.

crewAIInc/crewAI — Framework for orchestrating role-playing, autonomous agent crews.

The pattern I've settled on after a dozen of these projects: use crewAI to sketch out the agent roles and get stakeholder buy-in fast, then migrate the critical paths to LangGraph once you know where the failure modes actually live. They're not competing tools — they solve different parts of the problem. CrewAI gets you moving; LangGraph gives you control. The mistake is staying on the high-level abstraction too long and only discovering the edge cases in production, which is exactly what happened to me that autumn night.

One thing I still see underestimated: the cost of inter-agent communication. Every time one agent hands context to the next, you're potentially paying for a large prompt and risking information loss. Keeping task boundaries tight — so each agent gets only what it genuinely needs — is less glamorous than designing the agent roles, but it's where most of the efficiency gains come from. Treat the handoff schema as seriously as you'd treat a database schema. It deserves that level of attention.

“The agents are almost the easy part — the orchestration is the actual engineering problem, and most teams only discover that after their first expensive overnight run.”
