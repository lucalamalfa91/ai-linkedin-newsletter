Vector Search in Practice: Embeddings That Actually Retrieve Well

A concrete how-to for building vector search that returns relevant results, not just similar-looking ones.

July 29, 2026

Most vector search failures I see in enterprise projects aren't embedding model failures — they're pipeline failures. Wrong chunking strategy, no metadata filtering, embeddings generated at query time with a different model than at index time. The retrieval numbers look fine in a notebook and fall apart in production. This is the setup that avoids the common traps.

Rules I follow before indexing anything

  1. 1

    Fix your chunk size first

    For most enterprise docs, 512 tokens with a 64-token overlap is a reasonable starting point. Too small and you lose context; too large and the embedding averages out into noise.

  2. 2

    Store metadata alongside every vector

    Document ID, source, date, section type — at minimum. Without this you can't filter, and unfiltered retrieval at scale returns junk.

  3. 3

    Use the same model at index and query time

    Sounds obvious. I've seen it violated more than once when someone swaps the embedding model mid-project and forgets to re-index.

  4. 4

    Set a similarity threshold, not just top-k

    Returning the top 5 results regardless of score means you'll surface irrelevant chunks when the query has no good match. A cosine similarity floor of ~0.75 saves a lot of downstream hallucination.

Before you call retrieval 'good enough'

  1. 1

    Run recall@k on a real question set

    Write 20-30 domain-specific questions with known answers and check whether the right chunk appears in the top-k results. Eyeballing a few queries is not evaluation.

  2. 2

    Test with adversarial queries

    Short queries, typo-laden queries, queries that use different terminology than your documents. Embeddings handle paraphrase well but break on jargon mismatch.

  3. 3

    Check your re-ranking step

    A cross-encoder re-ranker on the top-20 results before returning top-5 will improve precision noticeably for enterprise use cases. It adds latency — usually worth it.
