Model Context Protocol (MCP)

MCP: One Protocol to Stop Reinventing Tool Plumbing

How Model Context Protocol finally separates the 'what tools exist' problem from the 'which model runs' problem.

November 6, 2026

A client asked me last autumn to wire their internal knowledge base into a chat assistant. Straightforward enough — until I looked at what they already had running: one team had built a custom Slack bot with its own search connector, another had a Python script that hit the same API but formatted results differently for a different LLM, and a third had just started doing the whole thing again from scratch because they didn't know the other two existed. Three integrations, same data source, zero reuse. That's the situation MCP is designed to kill.

Model Context Protocol is an open standard — originally from Anthropic, but now with broader adoption — that defines a single, consistent way for a model host (whatever is running the LLM) to discover and call external tools, read resources, and get context. The point isn't the protocol itself; it's the separation it enforces. You write a tool once, as an MCP server. Any MCP-compatible client — Claude Desktop, a custom agent loop, an IDE plugin — can call it without you touching the server code again. That's the trade-off worth naming: you pay an upfront cost in learning the protocol and standing up a server, and in return you stop writing bespoke glue code every time someone wants to connect a new model to an existing capability.

modelcontextprotocol/servers — Reference implementations and community MCP servers.

What I've found in practice is that the real value shows up the second time you need to connect something. The first MCP server you write feels like overhead. The second one, you're copying the scaffold and just swapping in the business logic — maybe twenty minutes of work. By the third, your colleagues are doing it without asking you. That compounding is the actual argument for adopting a standard over rolling your own function-calling convention. The failure mode to watch for is treating MCP as a magic interoperability layer when your tools have wildly different latency profiles or auth schemes — the protocol doesn't solve those mismatches, it just makes them show up in a consistent place, which is still better than before, but it's not free.

“A protocol you adopt once beats a convention you re-negotiate with every new model.”
