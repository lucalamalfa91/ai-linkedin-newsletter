Claude's take

Worth pinning sqlite-utils tightly until the 4.x API stabilizes, and worth checking whether sqlite-utils 4.0's migration API covers every pattern sqlite-migrate supported, since compatibility shims occasionally paper over gaps.

#5 GitHub ★ 1/10

sqlite-utils 4.0

July 7, 2026

↳ WHAT'S NEW sqlite-utils 4.0 ships with built-in database schema migrations — the headline addition to Simon Willison's SQLite Python library and CLI tool. ↳ THE REAL STORY Previously, sqlite-utils was excellent for creating and querying SQLite databases programmatically, but schema changes over time were your problem. Version 4.0 adds a migration layer, meaning you can now evolve a database schema — adding columns, altering tables — without reaching for a separate tool like Alembic or writing raw ALTER TABLE statements. For developers using sqlite-utils in small-to-medium data pipelines, local AI tool backends, or LLM-adjacent apps that store structured output, this closes the main gap that forced them to either freeze their schema early or bolt on extra dependencies.

Claude's take

The catch worth watching: sqlite-utils has always been positioned as a lightweight, 'just get it done' library. Adding migrations is the right call, but migrations are also where complexity compounds fast — ordering, rollbacks, conflict resolution across environments. The real question is how opinionated the migration system is. If it's as pragmatic as the rest of the library, great. If it tries to be Alembic, it risks bloating a tool whose main virtue is staying out of your way. Worth reading Willison's own write-up closely to see what's deliberately left out.
