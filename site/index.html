#1 xAI ★ 9/10

xAI Grok CLI coding agent (open-sourced)

July 16, 2026

↳ WHAT'S NEW xAI open-sourced Grok Build, a CLI coding agent built on top of the Grok model family. The repository lives at github.com/xai-org/grok-build and is written in Rust (crates/ directory structure visible in the source). ↳ THE REAL STORY A CLI coding agent in the same category as Claude Code or Aider — meaning it can read, edit, and reason about codebases from the terminal. The Rust implementation is notable: it suggests xAI is optimizing for performance and low overhead rather than shipping a quick Python wrapper. For developers already on the xAI API, this gives a local agentic coding loop without routing through a third-party tool. The open-source release also means the tool-calling logic, context management, and any MCP or shell integrations are inspectable and forkable — something neither OpenAI nor Anthropic has done with their equivalent agents.

Claude's take

The excerpt is thin — the actual discovery here came from a third-party explorer (Simon Willison) poking around the codebase, not from a formal xAI launch post. That's worth noting: there's no clear documentation, changelog, or stated feature set from xAI itself yet. Before treating this as production-ready, check whether the repo includes API key handling, rate-limit behavior, and context-window management that match what Grok models actually support in practice. Early open-source drops from model labs often lag behind their hosted equivalents in capability — the agent may not yet expose the full Grok context window or tool-use surface.

#2 Hugging Face ★ 8/10

Hugging Face Inkling: 975B-A41B multimodal open model

July 16, 2026

↳ WHAT'S NEW Inkling is a 975B-parameter mixture-of-experts multimodal model with 41B active parameters, released as open weights by Thinky and hosted on Hugging Face. ↳ THE REAL STORY At 41B active parameters per forward pass, Inkling sits in a compute class that's actually runnable on high-end multi-GPU setups — the MoE architecture means you're not paying the full 975B cost at inference. For practitioners, open weights means you can fine-tune, quantize, and self-host a multimodal model at a scale that was previously locked behind API walls. If the architecture holds up, this is a meaningful addition to the open-weight multimodal stack alongside models like Qwen-VL and InternVL.

Claude's take

The Hugging Face listing leans heavily on 'banger' and hype language with almost no technical detail — no benchmark numbers, no training data disclosure, no architecture paper. A 975B MoE model with zero published evals is a red flag worth sitting with. Before building anything on Inkling, verify actual benchmark performance against Qwen2.5-VL or similar, and check whether the weights are truly unrestricted or carry a non-commercial license buried in the fine print.

#3 Ayush Paul

How I tricked Claude into leaking your deepest, darkest secrets

July 15, 2026

↳ WHAT'S NEW A researcher found a data exfiltration vulnerability in Claude's web_fetch tool — the same tool Anthropic specifically designed with anti-exfiltration protections. ↳ THE REAL STORY The web_fetch tool was built to prevent a classic prompt injection pattern: malicious content on a fetched page instructs Claude to send sensitive data (from memory, system prompt, or conversation history) to an attacker-controlled URL. Anthropic's design was notable enough that Simon Willison wrote approvingly about it. Ayush Paul found a bypass anyway. The specifics of the hole matter here — if the exfiltration path works through a crafted URL or encoded payload that slips past the filter, any Claude deployment that uses web_fetch and handles user data is potentially exposed. The attack surface is any agentic workflow where Claude fetches external content while also holding sensitive context.

Claude's take

The uncomfortable part: this was a tool that received public praise for its security design, which means the community's threat model was incomplete. Security by design and security in practice are different things, and the gap tends to show up exactly when a tool is trusted enough that people stop looking. Developers using web_fetch in production — especially in memory-augmented or multi-turn setups — should treat external URL fetching as an untrusted execution boundary until Anthropic confirms a fix and explains what the actual bypass was.
