#1 Jon Udell ★ 9/10

Doctor, it hurts when agents create unreviewable PRs. Don't do that.

June 28, 2026

↳ WHAT'S NEW Jon Udell argues that AI coding agents are producing pull requests that are structurally unreviewable — too large, too opaque, or too entangled to meaningfully audit before merging. ↳ THE REAL STORY The problem isn't that agents write bad code. It's that they write code the way no senior engineer would let a junior engineer submit it: one massive diff with no logical decomposition, no commit narrative, no trail of reasoning. Human reviewers are then forced to either rubber-stamp the PR or spend more time reverse-engineering it than writing it from scratch would have taken. Udell's reframe is practical: don't think "human in the loop" (which implies the agent owns the process and you're a checkpoint) — think of the agent as a team member operating inside your existing workflow, which means your PR conventions, your commit granularity, your review standards still apply. The fix is upstream: constrain the agent's output format, not just its code quality.

Claude's take

The honest catch here is tooling. Most agent frameworks today are optimized for task completion, not for producing reviewable artifacts. Getting an agent to decompose work into atomic, well-described commits requires either significant prompt engineering or workflow scaffolding that most teams haven't built yet. Until that infrastructure exists, "agent follows our conventions" is a principle without a reliable implementation — and the path of least resistance remains merging the blob and hoping for the best.

#2 Interconnects ★ 7/10

Latest open artifacts (#22): Zyphra, Cohere, and Poolside are expanding the breadth of the ecosystem

June 28, 2026

↳ WHAT'S NEW Zyphra, Cohere, and Poolside have each dropped open or open-weight model releases, adding to a growing stack of non-OpenAI, non-Anthropic artifacts available to builders. ↳ THE REAL STORY The breadth argument matters more than any single release here. Zyphra is pushing on audio and speech-adjacent architectures. Cohere continues its enterprise-oriented open releases — models tuned for retrieval and structured business use cases rather than general chat. Poolside is coming from the code-generation angle, with training pipelines built around software engineering tasks. For a developer choosing a base model today, the decision tree is no longer just 'which frontier lab's API do I call' — it's increasingly 'which open artifact fits my fine-tuning budget and domain.' Each of these releases expands that decision tree in a different direction: modality, enterprise RAG, or code. The ecosystem is getting wider, not just deeper.

Claude's take

The honest question behind any 'open ecosystem expanding' narrative is motivation. Cohere releases open models while selling an enterprise API — the open weights are partly a developer acquisition funnel. Poolside has raised significant capital and releasing open artifacts before a commercial product is mature is a credibility play as much as a contribution. Zyphra is less legible commercially, which makes their releases more interesting scientifically but harder to bet a production system on. None of this makes the models less useful, but knowing why a lab opens something tells you how long they'll maintain it and whether the next version will also be open.
