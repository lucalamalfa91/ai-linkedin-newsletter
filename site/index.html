#1 Latent Space ★ 10/10

Vercel's Andrew Qu on why agents are a new kind of software

July 3, 2026

↳ WHAT'S NEW Vercel's Chief of Software Andrew Qu detailed the architecture behind eve, Vercel's internal agent framework, in a Latent Space interview — covering three core primitives: skills (discrete capabilities agents can call), sandboxes (isolated execution environments), and agent-readable websites (structured outputs designed for machine consumption rather than human browsers). ↳ THE REAL STORY The framing here is worth paying attention to: Vercel is treating agents not as a feature bolted onto existing infrastructure but as a distinct execution model that requires its own primitives. Skills replace monolithic tool definitions with composable, versioned capability units — closer to how you'd design a microservice than a prompt. Sandboxes address the containment problem that anyone who's run agent-generated code in production has already hit. The most underrated piece is agent-readable websites: if your product surfaces data through HTML designed for humans, agents will scrape it badly or miss it entirely. Vercel is betting that a parallel, structured rendering layer becomes a first-class concern for web developers.

Claude's take

The honest question is whether eve is a generalizable framework or internal scaffolding that happens to work at Vercel's specific stack. Companies with deep Next.js and edge-function investment will find the primitives natural; everyone else may find the abstractions leak. There's also a naming and standardization risk — 'skills' as a concept already competes with OpenAI's tools, Anthropic's tool_use, and LangChain's everything. Another layer of vocabulary without a cross-platform spec is friction, not simplification. Worth watching whether Vercel opens eve as a public SDK or keeps it as the engine behind their own AI products.

#2 Latent Space ★ 9/10

Skill engineering and the case against one-shot AI design

July 2, 2026

↳ WHAT'S NEW Paul Bakaus, via Latent Space, makes the case for 'skill engineering' — a design philosophy built around keeping humans meaningfully in the loop with AI agents rather than optimizing purely for autonomous, end-to-end task completion. The conversation centers on his product Impeccable and what he calls the 'loopmaxxing' era of AI development. ↳ THE REAL STORY The core argument: current agent architectures are being pushed toward one-shot, fire-and-forget execution, but that framing breaks down fast when tasks require taste, context, or judgment that wasn't fully specified upfront. Bakaus's position is that the design work — deciding where humans intervene, what they approve, and what they can safely delegate — is itself an engineering discipline, not an afterthought. For practitioners building agentic pipelines today, this reframes the question from 'how autonomous can I make this?' to 'where exactly does human judgment add irreplaceable value, and how do I make that handoff cheap enough that people actually do it?'

Claude's take

The honest tension here: 'keep humans in the loop' is easy to say and genuinely hard to implement in a way that doesn't just recreate the bottlenecks automation was supposed to remove. If every consequential agent action requires a human checkpoint, you've built an expensive approval queue, not an agent. The open question Bakaus's framing raises but doesn't fully answer — at least from the excerpt — is how you calibrate loop frequency without either micromanaging the model or discovering its mistakes three steps too late. Worth watching whether Impeccable's actual UX solves this or just makes the problem look designed.

#3 Latent Space ★ 8/10

The website of the future may assemble itself for every visitor

July 2, 2026

↳ WHAT'S NEW Adobe is experimenting with what it calls "agentic sites" — web pages that generate their layout and content dynamically based on each individual visitor's intent, rather than serving static or template-driven HTML. Carlos Sanchez discussed the concept at AIEWF, with coverage via Latent Space. ↳ THE REAL STORY The idea is a structural shift in how web content gets delivered: instead of a CMS pushing pre-authored pages, an agent interprets the visitor's context or query and assembles the page on the fly. For developers, this means the mental model moves from "build pages" to "define content primitives and intent-resolution logic." For practitioners building on top of Adobe's stack (Experience Manager, Target, etc.), watch for this to surface as an API layer where you pass user signals and get back rendered or structured content. The practical upside is hyper-personalization without maintaining thousands of page variants. The practical cost is latency, inference spend, and a much harder QA surface — you can't manually review every page that will ever exist.

Claude's take

The catch nobody is talking about yet: if the page assembles itself per visitor, SEO as we know it collapses. Crawlers index a snapshot; agentic pages have no canonical snapshot. Adobe has the enterprise relationships to push a new indexing standard, but Google and the crawler ecosystem would have to follow. Until that's resolved, any brand that depends on organic search traffic faces a real tension between personalization and discoverability. Also worth asking — who is liable when an auto-generated page surfaces incorrect product information or a legally problematic claim?

#5 Simon Willison ★ 7/10

llm-coding-agent 0.1a0

July 2, 2026

↳ WHAT'S NEW Simon Willison released llm-coding-agent 0.1a0 — an alpha coding agent built on top of his LLM Python library, which has been evolving toward a general agent framework. ↳ THE REAL STORY This is a proof-of-concept showing what a minimal coding agent looks like when assembled from the LLM library's agent primitives. For developers already using the LLM ecosystem (datasette, sqlite-utils, the llm CLI), this is the first concrete demonstration of the framework's agent capabilities applied to code generation and execution tasks. The 0.1a0 tag signals early alpha — not production-ready, but useful as a reference implementation for anyone wanting to build similar agents on the same foundation without reaching for heavier frameworks like LangChain or CrewAI.

Claude's take

The excerpt is thin on specifics — no tool list, no benchmark, no model requirements. The real question is how much of the 'agent' behavior is genuinely novel versus a thin wrapper around tool-calling that any LLM library already handles. Worth watching the GitHub repo for what tools it actually exposes (file read/write, shell execution, test runners) and whether Willison documents the failure modes. Alpha software from a solo developer moving fast is useful for learning the pattern, less so for building on directly.
