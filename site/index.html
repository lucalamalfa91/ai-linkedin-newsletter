Claude Tag: Multiplayer, Proactive, Persistent Agents in Slack

June 24, 2026

↳ WHAT'S NEW Claude is getting a Slack integration that supports multiplayer, proactive, and persistent agent behavior — meaning it can operate across conversations, respond to triggers without being explicitly summoned, and maintain context over time within Slack workspaces. ↳ THE REAL STORY This is a meaningful shift from the typical chatbot-in-a-channel pattern. Persistent context means Claude can track a thread of work across days, not just a single session. Proactive behavior means it can surface information or act on conditions without a human typing a slash command. Multiplayer means multiple teammates can interact with the same agent instance — shared state, not isolated DMs. For teams already living in Slack, this could replace a class of lightweight automation that currently requires Zapier, custom bots, or n8n pipelines.

Claude's take

The catch is trust and auditability. Proactive agents that act without explicit prompts in a shared workspace raise immediate questions: who authorized that action, what data did it read, and can you replay the decision log? Anthropic hasn't published details on permission scoping or audit trails for this integration. Until those are clear, putting this anywhere near sensitive channels — HR, legal, finance — would be premature. Watch for how workspace admins can constrain what Claude can see and do, not just what it can say.

#3 Simon Willison ★ 2/10

OPFS + Pyodide test harness

June 23, 2026

↳ WHAT'S NEW Simon Willison built a browser-based test harness combining OPFS (Origin Private File System) and Pyodide to explore whether Python code running in WebAssembly can read and write persistent SQLite files directly in the browser — no server required. ↳ THE REAL STORY This is groundwork for Datasette Lite potentially gaining persistent storage. Right now, Datasette Lite runs a full Python data analysis stack in the browser but loses everything on page reload. If OPFS + Pyodide can be wired together reliably, users could open a local SQLite file, query and edit it with Datasette's full interface, and have changes persist — all client-side. The test harness is Willison stress-testing the plumbing before committing to the integration: can Pyodide's file system layer actually talk to the browser's OPFS API without corruption or permission friction?

Claude's take

OPFS is still unevenly supported and its behavior inside SharedArrayBuffer-dependent environments like Pyodide gets complicated fast — especially around worker thread access and file locking. SQLite's WAL mode adds another layer of potential conflict when the same file is touched by both the OPFS layer and Pyodide's virtual FS. This harness will tell Willison whether the happy path works; the harder question is whether edge cases (concurrent access, large files, browser tab suspension) are tractable enough to ship to real users.
