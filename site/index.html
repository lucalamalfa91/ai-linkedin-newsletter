#1 Simon Willison ★ 9/10

datasette-agent 0.3a0

June 15, 2026

↳ WHAT'S NEW datasette-agent 0.3a0 adds execute_write_sql — a new tool that lets the agent write to a Datasette database after requesting explicit user approval, with permissions enforced at the Datasette layer. ↳ THE REAL STORY Previous versions of datasette-agent were read-only: useful for querying and exploring data, but you couldn't close the loop by having the agent actually modify records. With execute_write_sql, an agent can now run INSERT, UPDATE, or DELETE statements — but only after a human-in-the-loop confirmation step, and only within whatever write permissions the authenticated Datasette user holds. For developers building data-wrangling workflows on top of Datasette, this means the agent can go from "here's what I'd change" to actually making the change, without bypassing the existing auth model.

Claude's take

The approval gate is the right call, but the UX of that gate matters enormously. If approval is a simple yes/no prompt with no diff or preview of affected rows, users will rubber-stamp it — which defeats the purpose. Worth watching how the confirmation UI evolves: a tool like this is only as safe as the information shown at approval time. Also worth noting this is still alpha (0.3a0), so the write path shouldn't be anywhere near production data yet.
