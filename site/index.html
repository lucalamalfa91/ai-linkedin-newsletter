#1 Microsoft ★ 9/10

Building a hillclimbing machine: Launching seven new MAI models

June 2, 2026

↳ WHAT'S NEW Microsoft launched seven new MAI models, including MAI-Thinking-1 — a reasoning model with 1 trillion total parameters and 35 billion active parameters via a mixture-of-experts architecture. It is currently available only to select early partners, not the general public. ↳ THE REAL STORY The 1T/35B parameter split signals a MoE design similar to what's powering Mixtral and GPT-4 — large capacity on paper, leaner inference in practice. For developers, that active parameter count (35B) is the number that actually matters for latency and cost estimates. The "early partners only" gate means this is a benchmark and positioning play for now, not something you can wire into a production pipeline today. Microsoft is signaling it has first-party frontier model ambitions beyond just reselling OpenAI — the MAI branding is a deliberate flag planted in that direction.

Claude's take

The catch is the opacity. Seven models announced, minimal public access, and a blog post framing built around a metaphor ("hillclimbing machine") rather than benchmark numbers or API details. When a company leads with philosophy instead of evals, it usually means the evals aren't ready to lead with. Watch for whether MAI-Thinking-1 posts reproducible scores on AIME, GPQA, or SWE-bench before the early-partner window closes — that will tell you whether this is a real competitor to o3 and Gemini 2.5 Pro or a strategic announcement timed to a news cycle.

#2 Latent Space ★ 8/10

GitHub's plan for Agents

June 2, 2026

↳ WHAT'S NEW GitHub is laying out its architectural response to agentic coding workflows — the infrastructure and product direction meant to handle AI agents operating on repositories at scale, not just individual developers using autocomplete. ↳ THE REAL STORY Copilot shipped as a single-developer tool: one human, one editor, one stream of suggestions. Agentic coding breaks that model entirely. Agents open PRs, run in parallel, trigger CI pipelines, and read codebases autonomously — at volumes and concurrency levels GitHub's platform wasn't designed for. The strain is real: rate limits, permission models, and review workflows built for humans don't map cleanly onto agents that can generate hundreds of commits in an hour. GitHub's plan appears to be rethinking the primitives — how repos are accessed, how identity and permissions work for non-human actors, and how review surfaces adapt when the author is an agent rather than an engineer.

Claude's take

The honest question here is whether GitHub moves fast enough. The agentic coding toolchain — Cursor, Devin, Claude Code, Codex CLI — is already running on top of GitHub's infrastructure without GitHub's blessing or optimization. If the platform doesn't adapt its permission model, audit trails, and API rate limits to first-class agent support, developers will route around it or push toward platforms that do. GitHub has the distribution advantage, but distribution doesn't protect you if the underlying primitives are wrong for the workload.

#3 Simon Willison ★ 7/10

datasette-agent-micropython 0.1a0

June 2, 2026

↳ WHAT'S NEW datasette-agent-micropython 0.1a0 is an alpha plugin that runs AI-generated Python code inside a MicroPython sandbox within Datasette Agent — Simon Willison's hosted data exploration tool. ↳ THE REAL STORY The core problem with letting LLMs write and execute code is containment. MicroPython's stripped-down runtime is the containment strategy here: no filesystem access, no network calls, no standard library surface area that a model could abuse. If it holds, Datasette Agent gets a code execution layer without spinning up isolated containers or paying for a managed sandbox service. Willison notes GPT-4.5 hasn't broken out yet — which is a meaningful early signal, not a guarantee.

Claude's take

↳ WORTH WATCHING "GPT-4.5 hasn't broken out yet" is doing a lot of work in that sentence. MicroPython sandboxes have known escape vectors depending on which modules are exposed, and adversarial prompt injection through user-controlled data in a SQL query result is a realistic attack surface here — not just direct jailbreaking. The real test isn't whether a frontier model tries to escape unprompted; it's whether a motivated user can craft data that tricks the agent into running something it shouldn't. That's the audit this alpha still needs.

#5 Simon Willison ★ 3/10

micropython-wasm 0.1a1

June 2, 2026

↳ WHAT'S NEW micropython-wasm 0.1a1 is out — Simon Willison's package for running MicroPython compiled to WebAssembly, with fixes driven by his work on datasette-agent-micropython. ↳ THE REAL STORY The practical angle here is datasette-agent-micropython: Willison is building an AI agent layer for Datasette that runs Python in a WASM sandbox. MicroPython-in-WASM means untrusted or LLM-generated code can execute in a constrained environment without touching the host system — no subprocess, no filesystem access beyond what you explicitly expose. The 0.1a1 fixes address real friction he hit while wiring that up, so the limitations weren't theoretical.

Claude's take

MicroPython is not CPython. Any agent workflow that assumes the full standard library — or popular third-party packages — will hit walls fast. The interesting open question is how much of that gap matters when the use case is narrow SQL-adjacent scripting inside Datasette, versus how quickly it becomes a ceiling if the agent needs to do anything more general. Alpha versioning signals this is still being shaped by real usage, not a finished API.
