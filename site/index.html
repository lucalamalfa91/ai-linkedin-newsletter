#1 Simon Willison ★ 8/10

datasette-agent 0.3a0

June 15, 2026

↳ WHAT'S NEW datasette-agent 0.3a0 adds execute_write_sql — a new tool that lets the agent write to a Datasette database after requesting explicit user approval, with writes gated by Datasette's existing permission model. ↳ THE REAL STORY Previous versions of datasette-agent were read-only: useful for querying and exploring data, but you couldn't close the loop and have the agent modify anything. execute_write_sql changes that. The approval step means the agent proposes the write operation, a human confirms, and only then does it execute — which is the right default for anything touching persistent state. Critically, it respects Datasette's existing permission layer, so you're not bypassing whatever access controls you've already configured.

Claude's take

The interesting design question here is how much the approval UX actually protects you in practice. A human rubber-stamping AI-generated SQL at speed gets you most of the risk with little of the safety. The permission model integration is the more durable safeguard — but it's worth checking exactly which Datasette permission checks are being honored and whether there are edge cases around writable vs. immutable databases in your specific setup before trusting this in production.
